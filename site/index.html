What it grades

Six categories, weighted like a launch-quality scorecard. Warns cost half credit; passes cost none.

Documentation 20%

README that explains the repo in 15 seconds, plus install command, usage example and a real changelog.

Community 15%

License (permissive preferred), contributing guide, code of conduct, support channels, issue and PR templates.

Engineering 25%

Tests that run, CI that runs them, declared toolchain, committed lockfile — and a gentle flag when dependencies pile up.

Discoverability 15%

Description, at least three topics, homepage link and current activity, so search and social cards actually work.

Release hygiene 10%

A tagged release, readable notes and a tag that matches package.json — where stability actually lives.

Agent-readiness 15%

AGENTS.md, an installable skill, an MCP or manifest, llms.txt — the layer humans forget and AI agents read first.

Questions people ask first

Is my repo private?

RepoGrade only reads public GitHub metadata via the API: root file tree, README, package.json, releases. It cannot see private content and it never writes to your repo. Reports are generated locally and stay wherever you save them.

What happens with repos without package.json?

Package-specific checks (test script, engines, zero-deps, lockfile, tag match) cleanly skip and don't count against you. Any repo is gradeable.

Can this run in CI?

Yes — a composite GitHub Action ships in the repo, or call npx -p github:fastpresspages/repograde repograde owner/repo --fail-under 80 in your workflow to gate releases on the score.

Where do the weights come from?

Engineering is heaviest (25%) because broken basics hurt adopters most; agent-readiness is 15% because that layer is invisible to humans and decisive for AI-helpers. Say pull in the repo if you'd like a different weighting proposal — the scoring is an honest heuristic, not a law.
